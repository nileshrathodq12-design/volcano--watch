Build a complete, beginner-friendly, mobile-responsive web application called VOLCANO WATCH – Digital Seismograph Dashboard. This is a school science exhibition project. The application must use the Android tablet's BUILT-IN accelerometer. Do not require Arduino, external sensors, a laptop, or any additional hardware. 1. Design Create a modern scientific monitoring dashboard with: - Dark navy background. - Clean professional interface. - Green, yellow and red status indicators. - Large readable text suitable for displaying on a Samsung tablet. - Very few buttons. Do not create unnecessary menus or complicated settings. 2. Main controls Only include: - START MONITORING - STOP MONITORING - RESET 3. Live accelerometer readings Use the browser's DeviceMotionEvent API to access the tablet's built-in motion sensor. - Request motion sensor permission when necessary. - Read X, Y and Z acceleration. - Display live acceleration values. - Handle unsupported sensors and denied permissions with clear instructions. - Do not generate fake sensor readings. 4. Live seismograph graph Create a scrolling waveform graph showing vibration over time. - Use real sensor readings. - Remove the gravity component or use linear acceleration when available. - Make the graph smooth and easy to understand. - Clearly label the vertical axis and time axis. 5. Frequency calculation This is VERY IMPORTANT. Calculate the dominant vibration frequency in Hertz (Hz) from actual sensor readings. - Sample sensor data with timestamps. - Use an appropriate signal-processing method such as FFT or zero-crossing analysis. - Remove the baseline and gravity component before calculating frequency. - Display frequency in large text. - Display "Insufficient signal" when there is not enough reliable data. - Never invent or display random frequency values. - Explain that frequency estimates depend on the sensor's sampling rate and vibration quality. 6. Warning dashboard Create three demonstration-only vibration states: - GREEN: NORMAL - YELLOW: ELEVATED - RED: HIGH Use calibrated vibration amplitude thresholds, not frequency alone, to determine these states. Clearly mention that these are experimental demonstration levels, NOT real volcanic eruption predictions. 7. Technical requirements - Use plain HTML, CSS and JavaScript. - No complicated backend or database. - No login. - No paid APIs. - Must work on Android Chrome over HTTPS. - Make it responsive for Samsung Galaxy Tab A9+ and Samsung Galaxy Tab S6 Lite. - Include clear error handling. - Ask for sensor permission only after the user presses START MONITORING. 8. Final requirement Build the complete working application, not just a design mockup. Test the sensor access and frequency calculation logic. Provide simple instructions explaining how to open the app on an Android tablet and test it using gentle table vibrations. Make the interface extremely simple for a Class 10 science exhibition.
